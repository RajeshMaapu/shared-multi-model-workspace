## Root cause of the block

The installed daemon binary (Phase 3 install, pre-ISO) decodes
`CapabilityRecord.probedAt` with the default `JSONDecoder` Date strategy
(seconds since reference date). The dev `qualify` binary at commit
02047ec writes ISO-8601 strings and re-encoded the whole
`capabilities.json` (including the devin record) when it upserted the
kimi/managed record at 06:36Z. `workshop.reloadCapabilities` therefore
threw inside the store load, leaving `records = []` — every lane
unqualified — and devin's `resumed` wakeup hit the writer gate despite
a `qualified: true` record existing on disk. Restoring numeric
`probedAt` values makes the file readable by both binary generations
(the new codec accepts both).

## Open findings for follow-up

1. `capabilities.json` ISO `probedAt` is forward-incompatible with the
   installed (pre-ISO) daemon; any `qualify` run from a newer binary
   rewrites all records as ISO and silently empties the installed
   daemon's store on next reload. Either encode numeric until the
   installed daemon carries the compat decoder, or treat ISO as
   upgrade-gated.
2. The daemon had no SIGPIPE tolerance; a write to a closed ACP/HTTP
   channel killed the qualify process mid-run (exit 141, twice). Fixed
   in c53d12f; the installed binary still carries the defect.
3. `resumeTask` cannot recover a task parked `blocked` by the writer
   qualification gate once the gate is satisfied — no supported retry
   path observed.

### Root cause of the block

`ensureTaskWorkspace` → `WriterGenerations.begin` re-seeds each new
generation from the latest sealed/interrupted/review_only snapshot and
verifies its stored digest. The task's newest snapshot
(`writer-snapshots/d81492d6-…`, sealed pre-redesign) contains
`.devin/mcp_config.local.json`. `SafeTree` now excludes that file from
snapshot digests, so the recomputed digest differs from the recorded
one; `begin` throws "Sealed writer snapshot changed; review required",
which surfaces as "task workspace unavailable" and blocks the task.
This is a digest-semantics break across the upgrade, not user data loss.

  of observation — the retry scheduler either stopped after the task

- The seed-snapshot digest failure is permanent until handled:
  resuming will re-hit "Task workspace unavailable" every time.

### Open findings added

4. Pre-redesign sealed snapshots contain `.devin/mcp_config.local.json`;
   the new exclusion makes their stored digests unverifiable, so any
   v2 task whose latest seed snapshot predates the change cannot start
   a writer turn (`Task workspace unavailable`, permanent). Options:
   tolerate the mismatch for pre-change snapshots (digest fallback or
   a migration that rewrites snapshot/digest with the file removed),
   or fall back to the task workspace as the seed.
